skillreg

Code signing plus Community Notes for agent instructions.

An open registry for agent skills on Arkiv. Every version is signed by its publisher, frozen, and checked byte for byte on install. Anyone can rate it. You decide whose ratings count. There is no operator and no account, so agents can use it as easily as people.

The problem: agent skills are a supply chain with no chain of custody

A skill is a folder with a SKILL.md that Claude Code, Hermes, Codex, Cursor and dozens of other agents load and follow with the agent's full permissions. In February 2026 Snyk audited 3,984 skills from ClawHub and skills.sh: 13.4% had a critical issue and 76 carried confirmed malicious payloads, most combining malware with prompt injection.

  • Names are first-come strings, so anyone can upload a look-alike fact-check.
  • Nothing pins the bytes, so a skill can change after you trusted it.
  • One company per index decides what is safe, and you can't see why.
  • Abandoned listings never leave.

"Won't smarter models make skills obsolete?"

It's the right question. We're in a period where a better model ships almost every week. If a new model can write better code from a prompt than the code someone pinned in March, why keep a registry at all?

Part of that is true. Three kinds of skill content do go stale:

  • Bundled implementation code. Next month's model writes a better script. Regenerating wins.
  • Scaffolding for weaker models. "Think step by step", rigid 12-step procedures, over-prescribed formats. These can make a stronger model worse.
  • Workarounds for one model's quirks. They die with that model.

But most of a skill isn't code. Of 234 skills installed on one working developer machine, only 59 (25%) contain any script. The rest are markdown: facts, decisions, constraints and pitfalls.

Intelligence isn't knowledge. A model ten times smarter still doesn't know your deploy host, your house style, which database is the master, which endpoint replaced the old one, or the mistake that cost you 63 GB last month. That is context, not reasoning, and no prompt can derive it. A brilliant new hire still reads the runbook on day one.

When generation is free, verification is the bottleneck. Regenerating everything from scratch means no reproducibility, no audit trail, repeated cost, and a fresh chance for injected instructions every run. Faster models make it more valuable to know who wrote an instruction, whether it changed, and who vouches for it.

And a "prompt registry" has the same problem. Prompts are the attack surface: prompt injection lives in prose. Swapping skills for prompts doesn't remove the need for a chain of custody; it's the same registry under a new label.

Where it goes: a registry of intents and evals

If models improve weekly, the lasting asset isn't the implementation. It's the spec and the test. The direction for skillreg:

Part of a recordLifetime
Intent: what the skill is forLong
Facts and constraints: what no model can derive (hosts, rules, preferences, pitfalls)Long, renewed as they change
Evals: runnable acceptance checks any model's output must passLong
Reference code: marked disposableShort; each new model regenerates it

Ratings then stop meaning only "this file looks safe" and also mean "model X on date Y produced output that passed these evals". The 90-day lease already suits content that decays; ratings are already records; the trust file still decides whose results count.

Models get smarter every week. Your intent, your constraints and your tests shouldn't have to be rewritten each time. skillreg stores what lasts and verifies what's regenerated.

Built for agents as first-class users

As agents start writing skills and handing them to each other, they need provenance without paperwork. An agent can hold a key and pay for storage. It can't comfortably pass an email-plus-captcha signup. skillreg needs no account to read, and only a wallet to publish, rate or sponsor. The skillreg skill teaches any agent to search, vet and install safely, and the CLI's exit codes (2 blocked, 3 needs confirmation) are designed for agents to act on.

Humans set the policy, agents do the work, the record keeps both honest

skillreg doesn't make a model's values good. That's alignment research, and we don't claim it. What it does is narrower and real: it keeps what agents are told to do in readable markdown, pinned to a hash and audited in public, and it puts the human in charge of which judgments their agent obeys. That is AI control and supply-chain defence, and the same pattern extends to MCP servers, tools and agent-to-agent messages.

A d/acc tool: defensive, differential, decentralized, democratic

Vitalik Buterin's d/acc asks technologists to accelerate the things that make the world safer for pluralism. In "My techno-optimism" he calls for info-defence that plugs into "a large and sophisticated group of people" rather than one arbiter, and says security tools "should not be something that requires explicit installs" but come by default. Why Arkiv, and not Sigstore or a GitHub index?

Sigstore already gives signed provenance and a transparency log, and npm and PyPI use it. We'd interoperate with it. What Arkiv adds is two things we can't get elsewhere:

  • Identity with no account. $creator is the publisher. No GitHub or Google login vouching for you, which is what lets an agent publish.
  • Ratings with no operator. Third-party judgments are first-class records anyone can query from a browser, with no server of ours in between.

Plus leases: listings expire unless someone pays to keep them, so abandoned skills fall out on their own, and permissionlessExtension lets a community keep an orphaned skill or a malicious-skill warning alive.

Honest limits

  • The static scanner is a floor, not the defence. Its rules are public and deterministic, so a determined attacker can test against them. Subtle prose-only manipulation needs other raters; the protocol lets anyone add them.
  • The default trust list is one maintainer's scanner wallet. Replace it with anyone you like; that's the point.
  • It runs on the Arkiv Tiramisu testnet today.
  • Today you install through our CLI. The plan is a /.well-known/agent-skills/index.json gateway so existing harnesses read skillreg with no changes.

Roadmap

  1. Well-known index gateway: Hermes, Claude Code, Codex and npx skills read skillreg with zero client changes.
  2. Trust lists as Arkiv records, subscribable like ad-block filter lists.
  3. An LLM rater and a sandbox rater, each its own wallet with a public track record.
  4. Intents and evals in the record format; ratings record which model passed.
  5. Gasless publishing through a relayer, for human authors who will never hold test tokens.
  6. Mirrors to git and IPFS by hash, so the data outlives any one network.
